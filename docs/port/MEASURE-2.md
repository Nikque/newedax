# 計測の記録 2：v4.5.5-newedax.2 と C 版 v4.5.5-eval2.6、次の版の直し（2026-10-19〜20）

- 比べる相手は、C 版の配布物 v4.5.5-eval2.6（Windows の実行ファイルは PGO のビルド）と、Edax 4.5 の eval.dat を使うときは v4.5.5-nikque.18。どれも配布物の `config.ini`、eval.dat は配布物のもの。
- 1 スレッド：1 論理CPU に固定、2 つの実行ファイルを交互に（組ごとに順を入れ替え）、プロセスの CPU サイクルの比（new edax ÷ C 版）。組 0 は温めで数えない。節点数はすべて同じ（fforum-20-39：eval2 で 78,733,223、Edax 4.5 で 77,639,567）。中盤 30 局面は level 18（82,387,500 節点）。並べて流した計測（物理コアごとに 1 本）は揺れが ±1〜2% になるので 32〜48 組。
- 32 スレッド：論理CPU 32、ほかの重い処理を止めた PC、A B B A の順を 6 回、時間の比。
- 比が 1 より大きいと new edax が遅い。

## 2. 直し（`src/search/midgame.cpp`、`src/util/cpp_headers.h`）

PGO の版を C 版と比べると、MSVC の PGO が `get_moves` を呼び出し元に埋め込まず、独立した関数として中盤の約 17% を使っていた（C 版は埋め込む。命令の番地のサンプリングと map で確かめた）。

- 採ったもの：`mobility_eval`（eval2 の重みで葉ごとに 2 回）と、`NWS_shallow` の深さ 2 の `board_get_moves` を `EDAX_INLINE_CALLS`（MSVC 19.37 以降の `[[msvc::forceinline_calls]]`。ほかのコンパイラーでは何もしない）で埋め込む。PGO なしの組み立てでは機械語は変わらない（`.text` が同じ）。
- 試して採らなかったもの（どれも同じ条件で比べた）：`search_eval_2` の中の `search_eval_1` を埋め込む（悪化、+7〜8 KB）、`search_eval_2` を偶奇で分けない形に戻す（変わらない）、`vboard_flip`・`vboard_next` を埋め込む（悪化）、`get_moves` をすべての呼び出しで強制インライン（+47 KB）、`accumlate_eval` を `#pragma code_seg` で `.text` の先頭へ（PGO では効かない）、PGO の学習に Edax 4.5 の eval.dat の実行を足す（悪化）、PGO の学習に中盤 30 局面を足す（v3 で変わらない）、AVX2 の版で `eval_update_sse` を埋め込ませない（変わらない）、`search_eval_1` の `Ev` を 64 バイトの区切りの 0 バイト目・32 バイト目に置く（どちらも変わらないか悪化。32 バイト目では `-v4` の中盤が 0.961 → 1.006）。

## 4. HDD の book の読み込み

HDD（WD Red 1 TB）に、毎回キャッシュを通さずに（`xcopy /J`）写した 3,473 万局面の book（C 版が作ったもの。new edax はバケットの順が違うので 2〜3 回読む）を `book load` した。A B B A を 3 回。

- 時間：new edax ÷ C 版 = 0.914（回ごとに 0.80・0.99・0.95。中央値 27.5 秒 → 26.2 秒）。
- CPU 時間 8.3 → 3.8 秒、最大メモリ 3,243 → 1,667 MiB。

## 5. eval2 の道具（C の道具と交互に 16 回、並べた計測）

- `w2dat2`（W1〜W3）1.007〜1.009、`label`（L1）1.007、`playout`（O1）1.009（揺れが大きい）。ほかは同じか速い。
- `w2dat2` の差は 1 回あたり約 500 万サイクル（約 1 ms）。起動の費用は同じ（C++ 版が 0.14M サイクル少ない）。ソースの違いは入力の確かめだけで、原因は確かめきれていない。
- `label` の中身は本体の探索（`all.cpp`）で、Edax 4.5 の形の eval.dat を使う。起動の費用は C++ 版が 1.75M サイクル多い（1 回は約 31 億サイクル）。
