## 3. evsearch E1 の遅れ：原因と直し（6〜14 本目）

- 6 本目：E1 が変更前（`b8`）の 1.039 倍。7 本目は計測窓の 32 スレッドの計測と重なり、ばらつきで判断できなかった。
- 8 本目：反復 1・10・30 回で、遅れは反復によらない固定の分（+76M〜105M サイクル）。`ec2419c` はかえって悪い（1.08 倍）。
- 9 本目：`evtool.hpp` だけ新しくした版（vH）で 1.080 倍。何もしない命令を足した版（p16〜p48）は 1.000 倍だったが、11 本目の map で、この版では `features` が動いていなかったと分かった（この試しは無効）。
- 10 本目：段階ごとのサイクル数で、遅れはほぼすべて学習データの特徴の計算（`features`、+12.5%）。11 本目：`features` と `get_moves` の機械語は同じで、番地が 2,320 バイト動いていた。速さは `features` の 64 バイト内の位置とそろう（48：1.000、16：1.056、0：1.080）。CPU は AMD Ryzen 9 9950X。
- 12 本目：リンカの `/ORDER` は static 関数に効かない（LNK4037）。13 本目：`#pragma code_seg(".text$a1")` で区画に置くと、前に何も置かない形（s0）が b8 と同じ（反復 1 回 1.000、10 回 1.002）。前に 16・48 バイトを置くと 1.07〜1.08 倍に戻る。→ **原因は同じ機械語の置き場所（確かめた）**。s0 の形を `6993cf8` に入れた。
- 14 本目：E1 は C の 0.958 倍（12/12 で C++ が速い）、15 本目：b8 の 0.998 倍。
