# 設計：book.dat と eval.dat の新しい形（段階4、2026-10-17）

書いたのは Claude Opus 5.5。段階4（新しい形と変換）の設計。実装は同じ日に始める（設計書の確認の前に進める。変えたい所があれば実装を直す）。

## 1. 守ること

- 新しい newedax は、古い形（nikque.17 までの形、以下「形1」）と新しい形（以下「形2」）の両方を読む。
- book は形1⇔形2 の両方向に変換できる。変換で中身（局面・数・評価値・手・level）は変わらない。
- 形2 の eval.dat・book.dat は、古い実行ファイル（nikque.17 以前）が読み込もうとすると、はっきり断られる（違う magic）。
- 保存の既定は形1（edax_runner や配布済みの版がそのまま読めるように）。読んだ形を覚えて、その形で保存する。形は `-book-format` で選べる。
- 読み込みも保存も、形1 の今の速さとメモリを落とさない（形1 の処理はそのまま）。

## 2. book.dat 形2

### 2.1 ねらい

- ファイルを小さく（形1 は局面ごとに 42 バイト以上。形2 は多くが 27〜29 バイト、見積もり）、読み込みを速く（読むバイトが減る分）。
- 壊れたファイルを確実に見つける（CRC32C）。形1 は数の不一致でしか分からない。
- 拡張できる（頭の大きさ・必須の印・記録の種類を持つ。将来、欄を足しても古い newedax が「分からない形」と断れる）。
- 局面数を 64 ビットで持つ（今の newedax は 32 ビットまでしか扱わないので、超えたら断る）。

### 2.2 全体

```
頭（header_size バイト、今は 64）
局面の記録 × n_positions
尾（16 バイト）
```

すべて little-endian。（形1 は機械のまま。対象はすべて little-endian。）

### 2.3 頭（64 バイト）

| 位置 | 大きさ | 中身 |
|---|---|---|
| 0 | 8 | magic `"NEDXBOOK"` |
| 8 | 2 | 形の番号（2） |
| 10 | 2 | header_size（64。これより大きければ、知らない欄として読み飛ばす） |
| 12 | 4 | 必須の印（0。知らない印が立っていれば断る） |
| 16 | 1 | 書いた版（VERSION） |
| 17 | 1 | 書いた release（RELEASE） |
| 18 | 1 | 記録の種類（1 = 2.4 の形） |
| 19 | 1 | 0 |
| 20 | 8 | 日付：年（2）・月・日・時・分・秒（各 1）・0 |
| 28 | 20 | book の設定：level・n_empties・midgame_error・endcut_error・verbosity（各 4、符号付き） |
| 48 | 8 | 局面数 |
| 56 | 4 | 0 |
| header_size−4 | 4 | 頭の CRC32C（0 から header_size−4 まで） |

### 2.4 局面の記録（種類 1）

| 大きさ | 中身 |
|---|---|
| 8 | player の石 |
| 8 | opponent の石 |
| 1 | n_link（手の数） |
| 1 | level |
| 3 | value・lower・upper（各 1、符号付き。メモリの `Position` と同じ幅なので失うものはない） |
| 2 | leaf の score・move |
| 4〜20 | 4つの数（勝ち・引き分け・負け・続きのない線）、それぞれ LEB128（7 ビットずつ） |
| 2 × n_link | 手の score・move |

形1 との違いは、数を可変長に（多くは 1 バイトずつ）、評価値を 1 バイトずつに、leaf を手の前に。並びの順（バケットごと）は形1 と同じ（読み込みで局面を一つの塊に置ける：`book_load` の pool）。

### 2.5 尾（16 バイト）

| 大きさ | 中身 |
|---|---|
| 8 | 局面の記録のバイト数 |
| 4 | 局面の記録の CRC32C |
| 4 | `"BEND"` |

読むときは CRC を 16MB の読み込み単位ごとにまとめて計算する（局面ごとではない。CRC32C 命令で 1 バイトあたり 1 サイクル以下の見込み）。

### 2.6 読み込みの検査

形1 と同じ検査（手の数・level・手の升・局面の重複・数の一致）に加えて：magic・形の番号・必須の印・頭の CRC・記録の種類・局面数（ファイルに入る数か、32 ビットに入るか）・尾の magic・記録のバイト数・記録の CRC・尾のあとに何もないこと。

### 2.7 保存の形の選び方

- `Book` に `file_format`（読んだ形：1 か 2。新しい book は 0）を持つ。
- 選択肢 `-book-format <auto|1|2>`（既定 auto）。auto は読んだ形。新しい book（`book new`・`book import`、読めなかったファイル）は、置き換えるファイルが形2 の book なら形2、それ以外（形1、ファイルがない、book でない）は形1（2026-10-17 に変更。それまでは新しい book はいつも形1 で、形2 の book を読んだあと `book new` して同じ名前に保存すると形1 に変わっていた）。
- `book merge` で読む別のファイルも、どちらの形でもよい。
- `book_file_positions`（保存の前に、置き換えるファイルの局面数を見る）も両方の形を読む。

### 2.8 変換

- `edax -book-convert <入力> <出力>`：入力を読み、`-book-format` が 1 か 2 ならその形、auto なら入力と違う形で保存して終わる。
- 確かめ方：形1 → 形2 → 形1 で、日付を除いてバイトが同じ（`compare.py` と同じ比べ方）。形2 から読んだ book で、14 suite と同じ結果が出る（あとの計測で）。

## 3. eval.dat 形2

### 3.1 ねらい

- 自分を説明する：パターン（升の並び）・重みの数・手数の範囲・誤差の係数を持つ。段階5（64 パターン）のファイルを、今の 47 特徴のファイルと取り違えない。
- 古い実行ファイルは断る（magic が違う。古い版は「is not an Edax evaluation file」で止まる）。
- 壊れたファイルを見つける（CRC32C）。
- 誤差の係数（今はコードに固定、`eval_open` の EVAL_A〜EVAL_c）をファイルに置く。

### 3.2 形

```
頭（header_size バイト）
重み：n_plies × n_weights の 16 ビット（符号付き、little-endian）、手数 first_ply から
尾（8 バイト）：重みの CRC32C（4）、"EEND"（4）
```

頭：

| 位置 | 大きさ | 中身 |
|---|---|---|
| 0 | 8 | magic `"NEDXEVAL"` |
| 8 | 2 | 形の番号（2） |
| 10 | 2 | header_size |
| 12 | 4 | 必須の印（0） |
| 16 | 12 | version・release・build（各 4） |
| 28 | 8 | 日付（double、形1 と同じ） |
| 36 | 2 | n_plies（形1 からの変換では 60） |
| 38 | 2 | first_ply（0） |
| 40 | 4 | n_weights（1手数あたり、今は 114,364） |
| 44 | 2 | パターンの組の数（今は 13） |
| 46 | 2 | 0 |
| 48 | 48 | 誤差の係数 A・B・C・a・b・c（double） |
| 96 | 20 × 組の数 | 組ごと：升の数（1）・置く場所の数（1）・0（2）・詰めた重みの数（4）・最初の場所の升（12） |
| … | | 0 で header_size−4 まで |
| header_size−4 | 4 | 頭の CRC32C |

今の newedax は、組の表が内蔵の 47 特徴の表と同じで、手数が 2〜53 を含むときだけ読む（違えば「この build では使えない pattern set」と断る）。段階5で 64 特徴の表を足す。

### 3.3 変換

- `edax -eval-convert <入力> <出力>`：形1 → 形2、形2 → 形1（手数 0〜59 がそろっているとき）。重みはそのまま写す（詰めた形のまま）。
- 確かめ方：形1 → 形2 → 形1 でバイトが同じ。形2 を読んだ実行で fforum-20-39 の節点数が記録と同じ。

## 4. 速さとメモリ（考えたこと）

- 形1 の読み書きの道は変えない（関数の引数に形を足すだけで、局面ごとに分岐が1つ増える。予測はいつも当たる）。
- 形2 の読み込みは、数の LEB128 の解読（1 バイトなら分岐1つ）が増え、読むバイトが減る。CRC は読み込み単位ごとにまとめて。
- 形2 の保存は、数の符号化と CRC が増え、書くバイトが減る。
- メモリは変わらない（読み込みの 16MB の入れ物を使い回す）。
- 実際の速さはあとの計測（試験D と同じ時）で測る。29GB の実 book は使わない。
