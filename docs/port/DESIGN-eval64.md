# 設計：64 枠の評価関数の土台（段階5、2026-10-17）

書いたのは Claude Opus 5.5。`HANDOFF-eval4.md` の 5.1「0-1　64 枠の骨組みと速さ」の骨組みの部分。学習・対局・速さの計測はここに入らない（あとの作業）。

## 1. 何を作ったか

- コンパイル時の選択 `EVAL_SLOTS`（48 が既定、64 を選べる。`/D EVAL_SLOTS=64`、`-DEVAL_SLOTS=64`）。
- 48：今までと同じ。探索の関数の機械語は段階4と同じ（MSVC x64 AVX-512 `/O2` の一覧で、違うのは eval.dat を読む 5 関数だけ）。
- 64：特徴の枠 48〜63 に、10 升のパターン 4 組 × 4 か所を足す。
  - 特徴の値は 256 ビットのベクトル 4 つ（AVX2）、128 ビット 8 つ（SSE・NEON）、64 ビット 16 個（それ以外：`VECTOR_EVAL_UPDATE` を自動で選ぶ）。
  - 重み：`Eval_weight` に `X[4][59049][2]`（詰めない 3^10）。和は AVX-512 で gather 1 回、AVX2 で 2 回、汎用版で 16 項を足す。
  - 相手から見た特徴（`eval_pass`）は 3^10 の表 `OPPONENT_FEATURE` で。
- 追加の 4 組の升（`tools/port/gen_eval64.py` の `EXTRA`、`src/eval/eval_feature64.h` の `EVAL_X_SQUARE`）は**仮のもの**（大きさだけ実際に使いそうな 3^10 にした）。学習する評価関数のパターンは、学習の作業で決める（`HANDOFF-eval4.md` 2章の 7・8 の決まりに従う）。
- 特徴の表（各升が各特徴に足す値）は `gen_eval64.py` が書く。今の 48 枠の表（`eval.cpp`）を、特徴の升の定義（`EVAL_F2X`）とずれ（`EVAL_OFFSET`）から計算し直して一致を確かめ、それに追加の 16 枠を足す。`gen_eval64.py check` で、置いてある表が書き出すものと同じかを確かめられる。

## 2. eval.dat

- 形2 の組の表に、追加の 4 組（升 10、場所 4、重み 59,049、最初の場所の升）を足したファイルを読む。重みは 1 手数ごとに、詰めた 114,364 個のあとに 4 × 59,049 個（偶数の手数で手番側から見た添字。奇数の手数は `OPPONENT_FEATURE` で入れ替えて読む）。
- 64 枠のビルドは、13 組のファイル（形1、形2）も読む。追加の組の重みは 0 になるので、評価値は 48 枠と同じ。
- 48 枠のビルドは、17 組のファイルを「holds weights of patterns this Edax does not use」で断る。17 組のファイルは形1 に変換できない（断る）。

## 3. 確かめたこと（1論理CPU）

- 64 枠（追加の重み 0）の x64 AVX-512 で fforum-20-39 の1スレッドが記録どおり（77,639,567 節点）。
- 回帰 `evalslots`（48・64 どちらでも動く）：ランダムな 300 局で、1手ごとの更新（`eval_update`・`eval_pass`）が盤面からの計算（`eval_set`）と同じ。64 枠では、追加の 16 枠の値が `EVAL_X_SQUARE` から直接計算した値と同じ、追加の重みに乱数を入れたときの評価値の差が、その重みの和と同じ（18,116 局面）。さらに、乱数の重みを持つ 17 組のファイルを書いて読み、重みがすべて正しく入ること、形1 への変換を断ることを確かめた。
- 64 枠の `evalslots` を、x64 AVX-512（512 ビットの gather）・x64 AVX2・x64 SSE2・x86 SSE2・x86 `/arch:IA32`（更新は実行時に SSE2 を選ぶ道）で流して通った。`VECTOR_EVAL_UPDATE` の更新（SSE2 のない CPU の道）はこの PC では通らない（未確認）。
- NDK clang 18（aarch64・armv7a）で 64 枠の文法の確認（`-fsyntax-only -W -Wall -Wextra`）：新しい警告なし。実機での実行はしていない。
- 48 枠の quick_check：x64 AVX-512・x86 SSE の fforum が記録どおり、API 206 件、回帰 46 件。

## 4. 速さとメモリ（考えたこと。測っていない）

- 48 枠：探索の機械語が同じなので変わらない。
- 64 枠：1 手ごとの更新でベクトルの足し引きが 4/3 倍（AVX2）、評価の gather が AVX-512 で 3 → 4 回、AVX2 で 6 → 8 回。重みの表は 1 手数の組あたり 905KB → 1.85MB、全部で 23.5MB → 48.1MB（26 組。計算）。`Eval` の特徴の部分は 96 → 128 バイト。以前の試作の実測では、AVX2 で gather を 1 回足すと level 18 で x0.895（`HANDOFF-eval4.md` 4.2 の 5）。64 枠の費用は、追加の重みを 0 にした今の形で、別窓の計測で測る（評価値と節点数が 48 枠と同じなので、時間の差がそのまま 64 枠の費用になる）。
