## 2. 試験（`test_evtools.py`、書いただけで流していない）

| 試験 | 中身 |
|---|---|
| book_form2（書き換え） | 形1の book を `edax -book-convert` で形2にし、それを形1に戻したもの（同じ順）と、`bookdump` の出力のファイル・`bookscan` の出力が同じ。記録の 1 バイトを変えた形2、末尾を切った形2は止まる |
| trans2rec | Python で作った乱数の合法な 300 局（パスあり、大文字、行の後ろの欄、途中で終わる局を含む）について、記録と結果を Python でも計算して、出力のファイルと突き合わせる。正しくない手の行は止まる |

## 3. 速さ・メモリの見立て

- `bookdump`・`bookscan`：形1の読み込みは `fread` の回数が同じ。形2は LEB128 の数を 1 バイトずつ読み、CRC32C を表で 1 バイトずつ計算するので、形1より CPU を使う見込み（29GB の実 book なら CRC だけで数十秒の見積もり）。必要なら CRC32C 命令を使う形に直す。
- `evsearch -window k`：学習のデータが最大 2k+1 倍になり、メモリと時間もほぼ比例して増える（見立て）。k=0 は今と同じ。
- `selfplay3 -alt p`：探索が約 1+p 倍（見立て）。
